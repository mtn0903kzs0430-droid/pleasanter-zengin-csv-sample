# 導入手順書（管理者向け）

## 1. 準備

1. プリザンターの検証用領域と「サイトの管理権限」を持つ利用者を用意する。
2. 元JSONはPleasanter 1.5.2.0からの出力であることを確認する。導入先のバージョンを記録する。
3. 保存先指定機能showSaveFilePickerを使えるPC版Edge／Chromeを用意する。HTTPSを基本とし、localhost検証も環境で確認する。
4. JavaScript・サーバースクリプト・APIの実行可否、利用者の取得・更新権限を確認する。
5. 既存環境の変更を伴う場合は、既存サイトの設定・必要なデータを別途バックアップする。

ブラウザ保存機能には接続・ブラウザの制約があります。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)を参照してください。

## 2. フォルダ一式の新規インポート

1. 取り込み先のフォルダを開く。
2. 「管理」→「サイトパッケージのインポート」を開く。
3. `site-package/全銀CSV出力_v0.1.0.json`を選択する。
4. 元環境の権限は配布物から除去済み。画面でも「サイト／レコード／項目のアクセス制御を含める」をオフにする。通知・リマインダーもオフにする。
5. インポートする。親フォルダの中に「支払管理」「マスタ支払先」が作られたことを確認する。
6. 管理者がアクセスできること、必要な利用者が両テーブルへアクセスできることを確認し、権限を設定する。

サイトパッケージのインポートは**新規サイトの作成**です。既存サイトへの上書き更新には使えません。
同じJSONを繰り返しインポートすると別サイトが増えます。
公式手順：[プリザンター・サイトパッケージのインポート](https://www.pleasanter.org/ja/manual/managers-guide/manage-table/site-package/site-package-import/)（参照日2026-10-15）。

## 3. リンクと項目の確認

1. インポート後の支払管理とマスタのサイトIDを控える。元の10142・10177を固定で使わない。
2. 支払管理の「管理」→「テーブルの管理」でClassAの選択肢とリンクを確認し、新しいマスタを参照していることを確認する。
3. ClassA選択時にClassB/C/D/E/F/H/I/Jが同名項目へ転記されることを、架空マスタと新規支払で確認する。
4. 支払管理の銀行名・支店名・口座情報・登録番号が読取専用で、金額・振込指定日・摘要を入力できることを確認する。
5. マスタの必須・入力規則・注意書きと、支払管理の3本のサーバースクリプトを確認する。

同梱JSONの各サイトは内部参照を保持しています。通常はインポート時にIDが変換されますが、取込後の選択・転記まで確認してください。

## 4. 依頼人の設定

1. 支払管理の「管理」→「テーブルの管理」→「スクリプト」を開く。
2. 「楽天銀行 全銀CSV出力」の一覧用スクリプトで`const CONFIG`を検索する。
3. companyCode、companyName、branch、accountを自分の契約・口座情報へ変更する。
4. テーブル設定を保存し、一覧を開き直す。

```javascript
const CONFIG = {
    companyCode: '1234567890', // 例。銀行から通知された10桁へ変更
    companyName: 'ﾃｽﾄ',       // 例。委託者名へ変更
    branch: '201',             // 例。依頼人支店番号へ変更
    account: '1234567'         // 例。依頼人口座番号へ変更
};
```

画面版はログイン中の権限で$p.apiGet／$p.apiUpdateを使います。APIキーをスクリプトに埋め込む必要はありません。
CONFIGは利用者のブラウザへ配信される値なので、秘密情報の保管場所としては使わないでください。

## 5. 導入完了の確認

[テスト仕様](06_テスト仕様・検証状況.md)のT01～T12を検証環境で実行してください。
特に、出力対象の範囲、ファイル保存、出力情報更新、編集制限、リンク転記、利用者権限を確認します。
この配布用JSONでの新規インポート・権限変換は今回未検証です。正常に終わることを確認してから利用してください。

## 6. 既存サイトを保守する場合

このJSONで既存サイトを置換しないでください。現行設定をエクスポートし、差分と戻し方を確認してから手動で必要箇所を反映します。
別サイトへコピーすると復旧用localStorageのキーも変わり、旧サイトの未完了処理を新サイトで引き継げません。

## Excelから出力する場合

[Excel設定・操作手順書](09_Excel設定・操作手順書.md)を参照してください。Excelの設定・保存・復旧は同書に従います。ブラウザのlocalStorage操作をExcelの復旧に使用しないでください。
