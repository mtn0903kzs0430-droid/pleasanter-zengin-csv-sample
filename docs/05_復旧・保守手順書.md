# 復旧・保守手順書

## 1. メッセージごとの対応

|症状・表示|確認と次の操作|
|---|---|
|指定日に未出力がない|振込指定日と状況、取得権限を確認。行選択や一覧フィルタは出力条件になりません|
|金額・口座・受取人名エラー|示されたIDのレコードとマスタを確認。正の整数、桁数、半角カナ等を直す|
|対象または内容が変わった|並行編集を止め、対象を見直して「CSV出力」から再取得|
|保存先指定機能が使えない|対応するPC版Edge／Chrome、HTTPS等の接続環境を管理者と確認|
|通信・権限エラー|ログイン状態と対象サイトの取得・更新権限、通信状態を確認|
|CSV保存済み・更新未完了|CSVを再出力せず、下記の「更新を再開」を使う|
|前回の処理が未完了|同じブラウザ・接続先・サイトで復旧ボタンを確認する|
|出力済の内容を変更できない|状況だけ未出力へ戻して保存後、開き直して訂正|

## 2. CSV保存済みで更新だけ失敗した場合

1. CSVの保存場所・ファイル名・内容が正しいことを確認する。
2. 同じPC・ブラウザの同じ接続先・支払管理を開く。
3. 「全銀CSV出力」→「保存済みCSVの更新を再開」を押す。
4. 成功済みのレコードを除き、残りの出力情報を更新する。CSVは再作成しない。
5. 全件成功の通知と、一覧の状況・出力日時・ファイル名を確認する。

取得後に支払内容が変わった場合は更新を止めます。CSVと実データを管理者が照合してください。
更新を通す目的だけで支払内容を戻すことや、CSVを重ねて銀行へ送ることは避けます。

## 3. 保存できたか不明なまま中断した場合

1. 保存先の実ファイルを探し、空でないことと対象・件数・金額を確認する。
2. 復旧ボタンが出ていて正しいCSVを確認できた場合のみ「前回のCSV保存を確認したので更新する」を使う。
3. CSVが保存されていないことを確認できた場合のみ「未保存の処理を取り消す」を使う。
4. 不明な場合は再出力せず管理者に確認を依頼する。

通常の保存キャンセルや捕捉された保存失敗では復旧情報を消します。上記ボタンは、主に中断等で情報が残った場合に表示されます。
表示メッセージだけで実ファイルの有無を断定せず、保存先を確認してください。

## 4. 復旧情報が消えた場合

localStorageはブラウザ内の保存領域です。キーは接続先・サイトIDを含む`rakuten-zengin-status-pending-v3-...`です。
端末変更・ブラウザ変更・サイトID変更・サイトデータ消去では復旧情報を見つけられなくなる場合があります。
未完了処理中にサイトデータを消したり、JSONを取り込み直して別サイトへ移ったりしないでください。
消えた場合はCSVと支払レコードを管理者が照合し、銀行への送信状況も確認して個別に復旧方針を決めます。自動復旧機能はありません。

## 5. 保守・バックアップ

- 設定変更前に、実サイトからフォルダ一式JSONをエクスポートし、必要なデータも別にバックアップする。
- 出力済は振込完了の証拠ではないため、銀行側の処理結果と別に照合する。
- 出力CSVと必要な記録はアクセス制限のある場所へ保存する。公開リポジトリへ追加しない。
- 未完了の出力更新を解消してから設定変更する。
- JSを変えた場合は、JSON内の一覧スクリプトまたはサーバースクリプトにも反映し、差分とテスト結果を確認して新しい版にする。
- JSONの新規インポートは既存サイトの巻戻しではない。設定の戻しは変更前の設定と比較して行い、データは別途照合する。
- 問い合わせには版、導入先バージョン、ブラウザ、実行段階、エラー、個人情報を除いた対象ID・件数を記録する。APIキーや実口座情報をIssueへ貼らない。

## 6. Excel併用時

画面版とExcel版は同じ支払を対象にし得ます。片方だけの利用にするか、担当・時間を分けて同時出力を防ぎます。
Excel版のAPIキー環境変数・ブック・VBAは本配布物に含めません。画面版の導入にExcelは不要です。

## Excelの更新失敗・保守

[Excel設定・操作手順書](09_Excel設定・操作手順書.md)を参照してください。Excelの設定・保存・復旧は同書に従います。ブラウザのlocalStorage操作をExcelの復旧に使用しないでください。
