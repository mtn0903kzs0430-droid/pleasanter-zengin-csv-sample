# GitHub公開手順・未決事項

## 1. アップロードする範囲

**このREADMEがある配布フォルダの中身だけ**をリポジトリへ追加します。
案件全体のmaterials・work・過去outputs・実CSV・実行ログ・運用中のExcelブックを一括追加しないでください。
`excel/`にある初期化済みの配布用Excelだけを含めます。
作業中のローカルパスや引継ぎ記録は配布物へ含めていません。

公開コピーは元の最終JSONから、ユーザー・権限情報の除去、権限・通知・リマインダー取込フラグの無効化、
フォルダ並び順にある欠落サイト参照10141の除去を行っています。業務設定・一覧JS・サーバーJSは保持しています。
JSONに実レコードはありません。CONFIGは例示値です。サイトIDはパッケージの内部参照として保持しています。

## 2. 公開前に決めること

- リポジトリ名と公開範囲。
- ライセンス。今回は未選定のためLICENSEファイルを追加していません。再利用・改変・再配布の条件は決めてから追記します。
- 公開用JSONの新規インポートと通常操作テストを行うか、未確認のサンプルとして公開するか。

本資料は法的な利用許諾の判断を行いません。ライセンスが決まるまで、READMEから適用ライセンスを断定しないでください。

## 3. 公開前の確認順

1. `node tests/verify-package.cjs`と`node tests/browser-flow.cjs`を実行する。
2. `verification-result.txt`と[検証状況](06_テスト仕様・検証状況.md)を確認する。
3. 導入先でインポートを試し、可能なら実施記録を記入する。未確認は未確認のまま明記する。
4. CONFIGが個人の実口座や契約情報へ変更されていないこと、Dataが空であること、PermissionIdListが空であることを確認する。
5. Excelは配布用の1ファイルのみで、設定値・取得行・CSV確認・実行ログが空であることを確認する。使用後のブックを同名で差し替えない。
6. リポジトリの追加予定一覧を確認する。`.gitignore`は既に履歴へ入った情報を除去する機能ではありません。
7. GitHubの新規リポジトリへフォルダの中身を追加する。READMEは同梱品を使用する。
8. 公開後、READMEから各文書を開けることと、JSONをダウンロードできることを確認する。
