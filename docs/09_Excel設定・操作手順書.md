# Excel設定・操作手順書

配布一式：v0.2.0／Excel機能版：v1.1／更新：2026-10-16

## 1. 何ができるか

プリザンターから、指定日の未出力支払を取得し、楽天銀行の法人総合振込向け全銀CSVを保存します。
保存後、各支払へ状況900（出力済）、出力日時DateB、保存名DescriptionAを記録します。
「出力済」は銀行への送信・承認・振込完了を意味しません。

ブラウザからのCSV出力とExcelは、同じ支払管理に対する別の操作方法です。
同じ支払管理を複数人・複数タブ・複数ブックから同時出力しないでください。
本書のExcel操作はブラウザの保存ダイアログ・localStorageによる復旧とは異なります。

## 2. ファイルと必要な環境

- [配布用Excel](../excel/楽天銀行_全銀CSV出力_配布用_v1.1.xlsm)を、書き込みできるローカルフォルダへ展開して使用します。ZIP内や読み取り専用では実行できません。
- Windowsデスクトップ版ExcelとVBAマクロを使います。ブラウザ版Excel・Macでの動作は対象外です。Excelの各版・32/64ビットの網羅検証はしていません。
- プリザンターへ接続でき、対象の支払管理を取得・更新できるAPIキーが必要です。接続はHTTPSを使用してください。
- プリザンターを初めて導入するときは、先に[導入手順書](03_導入手順書.md)に従います。
- Windowsのダウンロード保護や組織の設定によってマクロがブロックされる場合があります。配布元とコードを確認し、組織の許可された方法で開いてください。Excel全体のマクロ設定を一律に緩める必要はありません。

## 3. APIキーを設定する（初回）

APIキーそのものはExcelに入力しません。Windowsのユーザー環境変数へ保存します。

1. 必要な権限を持つプリザンター利用者のAPIキーを用意します。
2. Windowsのスタート検索で「環境変数」を検索し、「環境変数を編集」またはユーザー環境変数の画面を開きます。
3. ユーザー環境変数へ、変数名 `PLEASANTER_API_KEY`、変数値としてAPIキーを登録します。
4. 開いているExcelの作業を保存して、Excelをすべて終了します。Excelを起動し直し、配布用ブックを開きます。

環境変数は暗号化された保管庫ではありません。同じWindows利用者で動くプログラムから読めるため、端末とAPI利用権限を管理してください。
APIキーを含む画面・環境変数値・設定済みブックをGitHubへ追加しないでください。

## 4. 「設定」シートの黄色い欄を入力する

|セル|設定内容|入力例・注意|
|---|---|---|
|B5|プリザンターURL|自分の環境のルートURL。例：`https://pleasanter.example.com`。`/items/12345`は付けない。サブパス構成ではその基点まで含める|
|B6|支払管理サイトID|JSON取込後に作られた「支払管理」のID。元環境のIDを流用しない。マスタや親フォルダのIDではない|
|B7|APIキーの取得先表示|`PLEASANTER_API_KEY`のまま。キーの実値は入力しない|
|B8|CSV保存フォルダ|存在するフォルダのフルパス。空欄ならこのブックと同じフォルダ。自動作成はしない|
|B12|委託者コード|銀行から通知された数字10桁。先頭0を保持する|
|B13|委託者名|契約上の依頼人名義。許可された半角文字40文字以内|
|B14|依頼人支店番号|数字3桁。先頭0を保持する|
|B15|依頼人口座番号|数字1～7桁。出力時に7桁へ0埋めする|

入力したら`.xlsm`形式のまま保存します。依頼人銀行番号0036・預金種目1はコードで固定されており、画面では変更できません。
設定欄が空の配布用ブックでは、実際の接続やCSV作成はできません。

## 5. 支払を登録してCSVを出力する

1. プリザンターで支払先と支払を登録します。振込指定日・金額・口座情報・状況100（未出力）を確認します。修正もプリザンターで行います。
2. Excelの「支払データ」シートで「全銀CSV出力」を押します。
3. カレンダーで振込指定日を選び、「出力へ進む」を押します。カレンダーは実行日の当月・本日から始まります。
4. 指定日の未出力全件を取得します。一覧で選択した行や表示中のページに絞る操作ではありません。APIキー利用者が見える範囲が対象です。
5. 表示された日付・件数・合計金額を確認します。「キャンセル」ならCSV保存・支払更新へ進みません。
6. 「OK」で、保存前に対象の変化を再確認し、設定フォルダへCSVを保存します。その後、支払管理の出力情報を更新して再取得で照合します。
7. 完了メッセージの保存フォルダ・ファイル名を確認します。全件更新成功後は「支払データ」A1へ戻ります。「実行ログ」も確認してください。

保存名は `楽天銀行_総合振込_振込日YYYYMMDD_作成YYYYMMDD_hhmmss.csv` です。
Excel版は自動命名で保存し、保存ダイアログは表示しません。同名ファイルは上書きせず停止します。
CSVは1（ヘッダー）→2（明細）→8（合計）→9（終了）の順で、半角カナを含むバイト列・CRLF改行で出力します。120バイト固定長形式ではありません。

## 6. CSV保存後に更新が失敗したとき

1. CSVは保存済みです。新しく出力せず、使用したブックとCSVを保持します。
2. 「支払データ」シートのO列（更新結果）を確認します。N列は保存名、P列は出力日時、Q列は保存先です。
3. 接続先・API権限・対象データを確認し、同じブックの「更新だけ再試行」を押します。
4. 「更新待ち」「更新失敗:」の行だけを再処理します。CSVは再作成しません。
5. 更新成功の表示、O列の「更新済」、プリザンターの状況・出力日時・保存名を確認します。

接続設定を別環境へ変えたまま再試行しないでください。未完了の更新がある場合は、新たな取得・出力を止める仕様です。
同じブックを開き直した場合も、保存された行と状態が復旧の基準になります。ブックを削除・初期化・別コピーへ交換しないでください。

CSV保存後、行へ復旧情報を記録する前やログ追記時に異常終了すると、再試行の対象が十分に残らない場合があります。
その場合は自動再出力せず、保存済みCSV・ログ・支払管理を突き合わせて管理者が確認します。銀行への重複送信にも注意してください。

## 7. シートの役割

|シート|役割|
|---|---|
|支払データ|取得データと更新状態の確認。編集不可。O列は更新結果|
|設定|黄色い入力欄のみ編集。非表示J列は内部処理用|
|CSV確認|生成内容を表で確認。ここを編集してもCSVへ反映しない|
|実行ログ|日時、処理、振込指定日、件数、金額、保存名、結果、詳細を記録|

マクロは処理中にこのブック自体も保存します。シート保護は誤編集防止用で、秘密情報の暗号化ではありません。
運用後のブックには支払先・口座・接続先・保存先・ログが残るため、配布用へ戻したりGitHubへ追加したりしないでください。

## 8. よくある停止と対応

|表示・状態|対応|
|---|---|
|環境変数が未設定|ユーザー環境変数を確認し、Excelをすべて終了して起動し直す|
|取得できない／APIエラー|URL、支払管理ID、APIキー利用者の取得権限、ネットワークを確認する|
|未出力レコードがない|振込指定日・状況・閲覧権限をプリザンターで確認する|
|出力先フォルダが存在しない|B8に存在するフォルダを指定するか、空欄にして保存済みブックの場所を使う|
|更新が一部失敗|O列を確認し、CSVを再出力せず「更新だけ再試行」を使う|
|取得後に内容が変わった|保存前なら内容を確認して取得し直す。保存済みならCSVと更新状態の確認を優先する|
